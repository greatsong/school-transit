# 학교 앞 교통

[공개 소스 저장소](https://github.com/greatsong/school-transit)

서울 학생이 학교를 검색하고 주변 버스 정류장·지하철역을 즐겨찾는 웹앱입니다. 로그인, 학생 이름, 집 주소, 기기 위치 조회, 분석 도구를 사용하지 않습니다.

## 실행

Node.js 22를 설치하고 이 폴더에서 실행합니다.

```sh
npm ci
npm test
npm run build
npm run dev
```

http://127.0.0.1:4318 에서 엽니다. 키 없이 실행하면 **예제 모드**입니다. 신도림중학교·당곡고등학교로 연습합니다. 예제 시간은 실제 운행 정보가 아닙니다. 버스 키를 입력하여 실행하려면 `npm run dev:secure`를 사용합니다. 키는 화면에 출력하지 않고 실행 프로세스에만 전달합니다.

## 사용 흐름

1. `/setup.html`에서 학교를 검색하여 등록합니다. 다음 방문부터 저장한 학교가 열립니다.
2. 지도에서 버스 정류장(학교 500m 이내)이나 지하철역(1.2km 이내)을 선택합니다. 거리 표시는 학교 중심 기준 **직선거리**입니다.
3. 버스 정류장 전체 또는 노선·방향, 지하철역을 즐겨찾습니다. 지도 위에도 예상시간이 표시됩니다.
4. 화면을 보는 동안 1분마다 조회하고, 그 사이에는 마지막 값을 기준으로 매초 계산합니다. 3분이 지난 정보는 시간을 숨깁니다. 시간이 0이 되어도 실제 도착을 확정하지 않습니다.
5. `학교에서 걸어가기`는 네이버 지도 **앱**의 도보 길찾기로 연결합니다. 앱 설치가 필요합니다. 웹 지도 링크는 목적지 검색용입니다. 앱 자체는 도보 소요시간·전체 대중교통 여정·환승을 계산하지 않습니다.
6. 공유 링크에는 현재 학교와 그 학교의 정류장·노선·지하철 즐겨찾기만 포함합니다. 개인 시간대와 다른 학교는 제외합니다. 공유 화면은 수신자의 기존 저장 설정을 덮어쓰지 않습니다.

학교·즐겨찾기·시간대는 localStorage에 저장합니다. 학교 설정 페이지에서 지울 수 있습니다. 시간대 기본 화면 설정은 현재 버스 정류장에 적용됩니다. 지하철은 역 전체를 즐겨찾으며 노선별 필터는 아직 없습니다.

## 필요한 키

| 환경변수 | 용도 | 신청·설명 |
|---|---|---|
| `SEOUL_BUS_API_KEY` | 서버 버스 정류소정보조회 | [공공데이터포털](https://www.data.go.kr/data/15000303/openapi.do) |
| `SEOUL_SUBWAY_API_KEY` | 서버 지하철 도착정보 | [서울시 지하철 실시간 도착정보](https://data.seoul.go.kr/dataList/OA-12764/A/1/datasetView.do)의 **인증키 신청(지하철)** |
| `NAVER_MAP_CLIENT_ID` | 네이버 지도 Web Dynamic Map | [Maps 등록 안내](https://guide.ncloud-docs.com/docs/maps-app) |
| `DEMO_MODE` | `true`이면 교통 API를 호출하지 않는 수업용 예제 | 선택 |
| `UPSTREAM_DAILY_LIMIT` | 버스 서버 인스턴스별 일일 요청 제한 (기본 900) | 선택 |

버스·지하철 인증키는 **서버 환경변수**에만 둡니다. `public/`, 공유 링크, Git, 브라우저 입력란에 넣지 않습니다. 지하철 키가 없으면 버스가 실시간이어도 지하철만 예제로 표시합니다. 네이버 Client ID는 공개 식별자이므로 브라우저에 전달됩니다. Client Secret은 이 앱에 필요하지 않습니다. 로컬 주소와 실제 배포 주소를 네이버 Maps 서비스 URL에 등록해야 합니다.

지도 키가 없을 때는 OpenStreetMap/Leaflet 지도로 위치를 확인합니다. 네이버 키를 넣으면 네이버 SDK를 사용하며 인증 실패 시 안내 문구와 목록을 표시합니다. 네이버 도보 앱 연결 자체는 API 키가 필요하지 않습니다. [공식 도보 URL 규격](https://guide.ncloud-docs.com/docs/en/maps-url-scheme)을 사용합니다. 학교 중심·역 중심은 교문·출입구·승강장과 다를 수 있습니다.

## GitHub → Vercel 배포

1. 이 폴더의 내용만 새 GitHub 저장소의 루트에 올립니다. 상위 DS Danggok 저장소 전체를 올리지 않습니다. `.env`, `qa`, `node_modules`, `dist`는 제외합니다. 소스 배포 ZIP에는 이 파일들이 들어가지 않습니다.
2. Vercel에서 해당 저장소를 Import합니다. Framework는 Other, Node.js는 22, Build Command는 `npm run build`, Output Directory는 `dist`입니다. 제공된 `vercel.json`이 API 함수와 빌드를 설정합니다.
3. Project Settings → Environment Variables에 필요한 키를 등록하고 배포합니다. 키를 변경한 뒤에는 다시 배포합니다.
4. 네이버 Maps에 배포 URL을 등록합니다. 배포 도메인이 바뀌면 다시 등록합니다.
5. 새 브라우저와 휴대전화에서 학교 등록, 실제 도착정보, 공유 링크, 네이버 도보 연결을 점검합니다.

**GitHub Pages 단독 배포는 실시간 API 서버를 실행할 수 없습니다.** Pages에는 정적 교재를 배포할 수 있으며, 앱은 Vercel 같은 서버 함수 지원 환경을 사용합니다. 웹앱의 공개 주소는 배포 완료 후 이 문서에 추가합니다.

## 수업과 수정

- 학생용: `/learn/index.html` (기존 DS Danggok 방식의 6개 실습, ①프롬프트 ②예제 코드 ③개선)
- 교사용: `/learn/teacher/index.html` (각 50분 진행안, 데이터 해석·한계 평가)
- 실행 예제: `node public/learn/examples.mjs`
- 제목·추천 학교: `public/site.js`
- 화면: `public/app.js`, `public/metro-ui.js`, `public/map-view.js`
- 서버: `api/arrivals.js`, `api/nearby.js`, `api/subway.js`
- 검사: `npm test`, `npm run build`, `npm run check:public`
- 부모 DS Danggok 교재 동기화: 부모 저장소 안에서만 `node scripts/sync-textbook.mjs`

## 운영의 한계

서울시 지하철 API 기본 안내는 하루 최대 1,000건입니다. 역 1곳을 1분마다 24시간 조회하면 1,440건입니다. 이 앱은 숨긴 탭에서는 자동 조회를 멈추고 서버 캐시를 사용합니다. 버스는 10초, 지하철은 55초 동안 같은 응답을 재사용하며 동시 요청을 합칩니다.

현재 호출 제한은 **프로세스별 메모리 제한**으로, Vercel 여러 인스턴스 사이에 합산되지 않으며 재시작하면 초기화됩니다. 학교 전체에 공개 운영할 때는 제공기관 한도 확인과 공유 캐시/전역 호출 제한이 필요합니다. 기존 설정은 개인 기기에만 있으므로 중앙에서 사용자별 사용량을 수집하지 않습니다.

학교 목록·역 위치는 스냅샷입니다. 역 목록은 좌표 자료와 이름으로 연결 가능한 서울·인접 지역 372개 역이며 전체 역·모든 출입구를 보장하지 않습니다. 신설·명칭 변경 시 출처를 확인해 갱신해야 합니다. 지하철 실시간 수신은 별도 키를 연결한 후 검증해야 합니다. 공식 API의 HTTP 구간은 서버에서만 호출하며 키가 포함된 주소와 원본 오류를 기록하지 않습니다.

지난 1주일 실제 도착 기록은 수집하지 않습니다. 배차간격과 과거 기록은 별도 데이터 검증이 필요한 후속 확장입니다. 수능 시험장 안내 역시 공식 시험장·교문·당일 교통 변경을 별도로 검증해야 합니다.
