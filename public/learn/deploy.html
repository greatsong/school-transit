학교 앞 교통

실행과 배포

🎯 예제 모드로 먼저 확인한 뒤 실제 키를 연결합니다.

1. 프로젝트 실행

Node.js 22를 설치하고 프로젝트 폴더에서 아래 명령을 순서대로 실행합니다. npm ci는 package-lock.json에 정해진 라이브러리를 설치합니다.

npm ci
npm test
npm run build
npm run dev

브라우저에서 로컬 앱을 엽니다. 키가 없으면 신도림중학교·당곡고등학교 예제로 연습할 수 있습니다. 프로젝트 제목과 추천 학교는 public/site.js에서 바꿉니다.

2. 키 신청

  • 서울시 정류소정보조회: SEOUL_BUS_API_KEY
  • 서울시 지하철 도착정보의 인증키 신청(지하철): SEOUL_SUBWAY_API_KEY
  • Google Maps JavaScript API: GOOGLE_MAPS_API_KEY

버스와 지하철 키는 서버에만 등록합니다. Google 지도 키는 브라우저에서 사용하므로 웹사이트 및 Maps JavaScript API 제한을 지정합니다. Google Cloud 결제 계정 연결이 필요합니다. 키 관리 콘솔에서 발급합니다. 길찾기 링크 자체는 키 없이 열립니다.

3. GitHub와 Vercel

  1. 새 GitHub 저장소에 school-bus-map 폴더의 내용만 올립니다. 상위 교재 저장소 전체를 올리지 않습니다. .env, node_modules, dist, qa는 제외합니다.
  2. Vercel에서 저장소를 가져옵니다. Framework는 Other, Node.js는 22, Build Command는 npm run build, Output Directory는 dist로 설정합니다.
  3. Environment Variables에 키를 등록하고 배포합니다. 키를 나중에 등록하거나 수정하면 다시 배포합니다.
  4. Google Cloud의 키 웹사이트 제한에 https://school-transit.vercel.app/* 등 실제 배포 주소를 등록합니다.
  5. 배포 주소에서 학교 검색, 버스·지하철의 실제 응답, 공유 링크를 확인합니다. Google 지도 연결을 확인합니다. 한국 도보 경로는 API 지원 제한이 있어 소요시간을 직접 입력합니다.

GitHub Pages는 이 교재 같은 정적 파일을 배포할 수 있지만 앱의 API 서버를 실행하지 못합니다. 실시간 앱은 Vercel 같은 서버 기능을 지원하는 환경이 필요합니다. 공개 저장소 주소는 운영자가 만든 뒤 교재에 추가합니다.

4. 공개 운영 점검

현재 호출 제한은 서버 프로세스별 임시 제한입니다. 여러 서버가 실행되면 합산되지 않습니다. 학교 전체가 사용하는 공개 서비스는 API 한도를 확인하고 공유 캐시와 전역 호출 제한을 추가해야 합니다. 화면이 숨겨지면 이 앱의 자동 조회는 일시정지합니다.

검증 결과에는 성공한 항목뿐 아니라 아직 키가 없거나 기기에서 확인하지 못한 연결도 적습니다. 복제한 배포의 지하철·Google 지도는 각각 키를 연결한 뒤 확인해야 합니다.
